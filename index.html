SQL / RDBMS

LocalFind Relational Database Architecture

Formal entity relationship schema adhering to normalization & indexed foreign keys

1:N Categories → Businesses
One category houses multiple service providers.
1:N Locations → Businesses
One city/neighborhood indexes multiple businesses.
1:1 Business ↔ Subscription
Active paid tier triggers Featured Listing placement.
Normalized Database Tables
table: `businesses` Primary Entity
  • id (UUID, PK)
  • owner_id (UUID, FK → users.id)
  • category_id (VARCHAR, FK → categories.id)
  • location_id (VARCHAR, FK → locations.id)
  • name (VARCHAR 150)
  • phone, whatsapp, email (VARCHAR)
  • price_tier (ENUM: '₹', '₹₹', '₹₹₹')
  • is_verified (BOOLEAN, DEFAULT FALSE)
  • is_featured (BOOLEAN, DEFAULT FALSE)
  • created_at (TIMESTAMP)
table: `subscriptions` Monetization
  • id (UUID, PK)
  • business_id (UUID, FK → businesses.id)
  • plan_type (ENUM: 'FREE', 'FEATURED', 'PREMIUM')
  • monthly_amount (DECIMAL 10,2)
  • billing_status (ENUM: 'active', 'overdue', 'cancelled')
  • valid_until (TIMESTAMP)
table: `reviews` 1:N
  • id (UUID, PK)
  • business_id (UUID, FK → businesses.id)
  • author_name (VARCHAR 100)
  • rating (TINYINT 1..5)
  • review_comment (TEXT)
  • created_at (TIMESTAMP)
table: `business_images` 1:N
  • id (UUID, PK)
  • business_id (UUID, FK → businesses.id)
  • image_url (VARCHAR 500)
  • is_cover (BOOLEAN)
  • display_order (INT)
